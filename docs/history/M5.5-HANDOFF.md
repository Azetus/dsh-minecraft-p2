## 4. 关键约束（容易踩）

- **每个 body epoch 都会重置 enablement**：装/卸包或重启后，act/behavior 必须重新 `p2_check` + `p2_activate`，且每轮都要对当时用到的 artifact 做一次。
- **控制独占**：默认只有一个 active control；`jump` 声明为 `concurrent`，可与一个独占控制共存（`pillar` 已封装这条路径，不要手工拼 `jump`+`place` 时序）。
- **`blocks.exposed`**：不带该参数时 `findBlocks` 会返回整块区块内的方块（含埋藏矿石，相当于透视）；实验里找矿应使用 `exposed: true`。
- **`craft`**：逐次执行，合成后等背包增量（≤800ms）、两次之间 400ms；不足会返回 `CRAFT_INCOMPLETE`（带 requested/crafted/produced）。
- **`place`**：目标不能与 bot 身体重叠（`PLACE_BLOCKED_BY_SELF`）；`equip`/`place` 前会自动同步背包窗口。
- **`container`/`offers`**：pending 查询，执行器会轮询；`p2_observe` 也支持（默认 3s，可传 `timeoutMs`）。
- **`sleep`**：只能在夜晚；`stop()` 会 `bot.wake()`。
- **`goto`**：`canDig=false`、禁止跑酷、最大落差 3——不会挖方块开路；需要下矿请用行为按阶梯挖。
- **`pillar`**：需要手持方块、脚下有支撑；每次最多 8 格。

## 6. 已知基线缺口

- `capabilities` 未纳入 `bindingId`（binding 仍由 body manifest 计算）。
- `provider.manifest.json` 里的能力列表是旧值，运行时以 provider 为准，但不读它。
- `dig`/`craft` 等异步 op 是轮询语义，不是服务端确认。
- `place` 无法放置需要特殊朝向的两格结构（床可，门/箱子未验证）。
