# M5 G3 判定

> 2026-10-28。依据 [G2 报告](M5-G2-REPORT.md)、[G2 证据](M5-G2-EVIDENCE.md) 与 M5 G2 冻结基线。
> 本文只判定「IR 与 policy 的表达路线是否继续」，不把 M5 阶段宣布为完成：隔离与真实扰动门槛仍未闭合（§6）。
> **后续（2026-10-28）**：现已启动 behavior IR vs 受限 JS 的对照实验（[实验计划](EXPERIMENT-BEHAVIOR-SUBSTRATE.md)）。实验期间 IR 仍是 `dev` 主线；若实验结论不同，将以新 decision 显式修订本文，不默认推翻。

## 1. 判定

**继续采用小 IR（v1 内核），不进入替代方案对照。**

不引入 `select` / `aggregate` / `forEach` / `call` / policy 表达式；保持「小计划 + policy 决策 + act 执行 + op 原子能力」的分工。

## 2. 依据

| 证据 | 结果 |
| --- | --- |
| S1 拾取最近掉落物 | 通过（`succeeded`，背包 1；反例 `TARGET_GONE`） |
| S2 持续巡逻 | 通过（`A,B,C,A,B,C` 后 stop → `cancelled`；反例 `MOVE_TO_BLOCKED`） |
| S3 有限采集 | 通过（`dirt=4`；反例 `INSUFFICIENT_RESOURCE`） |
| S4 途中拾取再继续 | 通过（拾取后重发未到达的 B，再到 C） |
| V1 最远优先 | 通过（只换 policy，计划/act 不变） |
| V2 往返巡逻 | 通过（`A,B,C,B,A`） |
| V3 达标后返程 | 通过（库存 4、距 home 0.65 格） |
| V4 目标未获得即失败 | 通过（确定性注入，`TARGET_GONE`） |
| 可读性 | 独立 agent 复核：补状态前 2/4，补 `activeNode`/`activeTarget` 后 **4/4** |

关键事实：

- **没有任何场景要求修改执行器、节点集或表达式语义。** `length` 与 `entities` 过滤在冻结前加入（G1），冻结后只新增 status 诊断字段。
- **策略没有逃入 act。** 三个内置 act 都是单 op 包装；behavior/policy 只做编排与决策。
- **取消与收尾由平台承担。** 两个持续场景的停止都由外部 stop 完成，作者代码没有停止标志。
- **计划可读。** 复核者能在扩展后的 status 上区分分支、目标、下一步与失败出口。

## 3. 为什么不是另外两类

- **不是「触发替代方案对照」**：需要「至少两个场景或变体必须增加核心语义，或只能靠隐藏完整策略实现」。实际为 0 个；V3 的写法不直观，但仍在冻结内核上完成，未要求新语义。
- **不是「暂不能判断 IR」**：IR 的表达证据已足够（四个主场景 + 四个反例 + 四个变体 + 可读性）。隔离未完成影响的是「能否信任自定义代码」，不是「IR 能否表达策略」；按本报告的区分，它列为 M5 阶段门槛（§6），不推翻 IR 判定。

## 4. 观察项与触发条件

判定为「继续」不等于没有代价。以下四项需要持续观察，并为每一项预设触发条件，避免以后用「再加一个节点」默认解决：

| 编号 | 观察 | 现状 | 触发重新评估的条件 |
| --- | --- | --- | --- |
| C1 | 多阶段任务缺少「阶段推进/break」 | V3 只能把返程写成循环内幂等尾动作，靠完成条件拦截；写法不直观 | 出现**第二个**必须分阶段且无法用幂等尾动作清楚表达的场景 → 评估一个有界 `repeatUntil`/阶段原语，而非引入 JS |
| C2 | 精确引用导致换 policy 仍需新 behavior artifact | V1/V2 均出现；计划与 act 未变 | 若多数参数化调整都要复制 behavior，考虑 builder 级「按定义名解析」的工程糖，不改变核心语义 |
| C3 | 隔离尚未实测 | runner 是 `node:vm` 基线；S1—S7 未执行，`ISOLATION.md` 证据表为空 | M5 阶段门槛，见 §6；不得以 G3 通过替代 |
| C4 | 共享 runner 的故障耦合 | policy 超时重建会影响活动 act 的语义已写入契约，但未实测 | 允许 policy 进入 guard / act 运行期求值，或观察到实际耦合时，评估独立 policy runner |

另外两项非 IR 但影响交付的观察：

- **可读性复核者是 agent，不是人类。** 4/4 是按「非作者、只读计划与文档」的口径取得的；建议后续由人类复核一次，不作为 G3 阻断。
- **V4 的注入方式与规格原文不同。** 规格写「移除目标」，实现用「不可拾取物品」触发同一条声明失败路径；两者不等价，但在验收标签上一致，已记录。

## 5. 明确不做的事

- 不把 `forEach` / `call` / 集合算子加入 v1；没有场景证据支持。
- 不把 policy 放进表达式求值位置；跨进程等待只允许 `decide` 一种形态。
- 不在 G3 之后拆独立 policy runner；先补隔离证据。
- 不用「再加一个控制节点」回应单个场景的表达不顺；先看 C1 的触发条件。
