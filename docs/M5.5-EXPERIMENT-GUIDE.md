# M5.5 实验指导（给新 session 的 DSH）

> 2026-10-28。本文用于在新 session 中操作 IR / JS 两个 behavior 分支的生存实验。
> 新 session 没有此前对话上下文；先完整读本文，再读 [ARCHITECTURE.md](ARCHITECTURE.md)、[BEHAVIOR-JS.md](BEHAVIOR-JS.md)、[BASELINE-OP-ACT-SMOKE.md](BASELINE-OP-ACT-SMOKE.md)。
> **不要合并分支、不要 push、不要安装/升级插件（由人类完成）。**

## 1. 设计前提（必须理解）

- **agent（你）是大脑**：观察世界、判断局势、选择/切换 behavior、决定何时写新策略；聊天与协作也由你处理。
- **behavior 是无智能的策略程序**：表达一段持续生效的行动策略（探索、采集、战斗、跟随、建造……），不承担“要不要铁镐、去哪找矿”的规划。
- **act 是技能**：单目标、可停止、有边界；用 op 完成动作。
- **op 是原子能力**：查询或控制；behavior 不得直接引用 ControlOp，只能通过 act。
- **policy 是 behavior 内部的状态转移条件/选择器**，不是 agent 的决策层，更不是规划器。

本次实验只比较 **behavior 的表示与执行方式**：IR 节点树 vs 受限 JS 生成器协程。op、act、policy、provider、body、工具面两边一致。

## 3. 人类准备

1. 两个**种子相同**的新生存世界，分别标记 `IR` 与 `JS`；同一个 LAN 端口 `25575`。
2. 每个世界同一个已 op 的 `P2_Operator`（用于搭场地、备份/恢复、必要时救援）。
3. 世界设置两边一致：难度、时间、gamerule、初始背包（建议空背包、正常生存）。
4. 每个世界开始前备份；实验期间不要改种子/版本/加载器。
5. 安装当前分支对应 bundle，启动 P2 body，确认工具可见。

## 4. 每个 bundle 的首次检查

安装后先做工具级 smoke，**不要运行 `scripts/baseline-smoke.mjs`**：该脚本会另起一个 body/`P2_Bot`，与已安装 bundle 冲突。

1. `p2_status`：body 在线、`version` 为对应 `0.3.3-exp-*`、`connection=connected`、无活动 run；`rescue` 段与预期配置一致。
2. `p2_observe`：`position`（含 dimension）、`inventory`、`health`、`time`、`block`、`blocks` 各一次。
3. `p2_check` 一个 act（`artifactKind:'act'`）→ `p2_activate`；再 check/activate 一个 behavior。
4. `p2_switch` 启动一个短 behavior；`p2_status` 看 activeAct/activeNode/activeTarget/waiting；`p2_stop` 结束。
5. 确认没有残留控制、没有旧 run 推进；再开始正式实验。

> 工具契约：`p2_check` 需要 `artifactKind`（behavior/act/policy）；JS behavior 必须额外传 `format:'js'`，否则会按 IR 解析。

## 4.1 救援通道（实验专用）

目的：实验期间不依赖人工 tp/给物品；卡住、被困、死亡循环、血量/饥饿危机时，由 agent 调用受控救援工具。**它不是 behavior/act 的 op**，behavior/act 看不到也不能调用；只有 DSH 的 `p2_rescue` 工具可用。

### 前置

- `P2_Bot` 必须是 op（至少 level 2）；这是人类准备，不是实验干预。
- `.p2/config.json` 增加：

```json
{
  "minecraft": { "...": "..." },
  "experiment": { "allowRescue": true, "rescueTpRadius": 32 }
}
```

默认关闭；每个世界开始前由人类开启。

> 配置只在 body **启动时**读取一次。改完 `.p2/config.json` 必须 `/p2 stop` → `/p2 start`，否则运行中的 body 仍是旧值；`p2_status.rescue` 可用于确认当前生效值。

### 允许的动作

| action | 命令 | 限制 |
| --- | --- | --- |
| `tp` | `/tp @s <x> <y> <z>` | 只传自己；距当前位置 ≤ `rescueTpRadius`（默认 32）；y 在 -64..320 |
| `effect` | `/effect give @s minecraft:<effect> <duration> <amplifier>` | 仅 `instant_health` / `regeneration` / `saturation`；duration 1–10 秒；amplifier 0–1 |
| `respawn` | `/kill @s` | 仅用于卡死/死亡循环；会掉落背包 |

不允许：`give`、`setblock`、`fill`、`gamemode`、`op`、远距离 `tp`、时间/天气/gamerule、其他 effect。工具不接受自由文本命令。

### 调用规则

1. 必须先 `p2_stop` 当前 behavior；有活动 run 时返回 `RESCUE_BUSY`。
2. 必须提供 `reason`（≥3 字符）与 `category`：`stuck` / `trapped` / `death_loop` / `health` / `food` / `other`。
3. 每次调用返回 `auditId`、命令、调用前 position/health，并追加写入 `.m5-runs/rescue.jsonl`；工具结果会进入 session 上下文。
4. 命令是 fire-and-forget：调用后必须 `p2_observe` 位置/血量确认，并把实际结果写进实验日志。
5. 失败码：`RESCUE_DISABLED`（未开）、`RESCUE_BUSY`（有活动 run）、`RESCUE_TOO_FAR`（超半径）、`RESCUE_INVALID`（参数/理由非法）。
6. 如果工具列表没有 `p2_rescue`：先确认安装的是 `0.3.2-exp-*`（`0.3.1` 包缺少工具注册）；停止 body、卸载旧包、安装新包后重试。`p2_rescue` 只在 `/p2 start` 之后注册。

### 公平性与记录

- 两个分支的救援能力、白名单、半径完全相同；不存在 branch 专属救援。
- 救援命令**不计入策略成功**；如果它直接带来资源/位置推进，该段标记为“受救援影响”，不用于表达力对比。
- 使用频率、场景、前后状态要记录；某分支需要更多救援是稳定性/可观测性的证据，不是表达力结论。
- 每个世界开始前记录配置；结束时统计救援次数与类别。

## 5. 内容编写

### 5.1 目录

- behavior：`behaviors/*.mjs`
- act：`acts/*.mjs`
- policy：`policies/*.mjs`

### 5.2 IR behavior（`exp/behavior-ir`）

当前形态：`export default { id, mode, parameters, locals, root, completion }`，节点见 [IR.md](IR.md)。示例：

```js
export default {
  id: 'gather-ore',
  mode: 'finite',
  parameters: { want: { type: 'number', required: true } },
  locals: { done: { type: 'number', initial: 0 } },
  root: { kind: 'repeat', id: 'loop', child: { kind: 'sequence', id: 'step', children: [ /* query / decide / act / assign */ ] } },
  completion: { kind: 'predicate', condition: { kind: 'expr', expr: { kind: 'binary', op: 'gte', left: { kind: 'local', name: 'done' }, right: { kind: 'param', name: 'want' } } } },
}
```

### 5.3 JS behavior（`exp/behavior-js`）

初版形态：`defineBehavior({ manifest, run })`，`run` 是生成器；`ctx` 支持：

`query`, `act`, `decide`, `wait`, `progress`, `log`, `succeed`, `fail`, `fresh`, `params`, `runId`, `now`。

示例：

```js
defineBehavior({
  manifest: {
    id: 'gather-ore',
    mode: 'finite',
    parameters: { want: { type: 'number', required: true } },
  },
  *run(ctx) {
    let mined = 0
    while (mined < ctx.params.want) {
      const pick = yield ctx.decide('pick-ore', { /* snapshot */ })
      if (pick.kind === 'none') return ctx.fail('NO_CANDIDATE', 'no ore visible')
      yield ctx.act('move-to', { x: pick.x, z: pick.z })
      yield ctx.act('mine-one', { pos: pick.pos })
      mined += 1
      yield ctx.progress({ mined })
    }
    return ctx.succeed({ mined })
  },
})
```

检查时用 `format:'js'`。不要用 `import`/`require`/`process`/`eval`/`Function`；不要 `async/await`；I/O 只能通过 `yield ctx...`。

### 5.4 新 act 的公平性

实验中需要新 act 时：

1. 在当前分支实现，检查/激活；
2. 把**同一份 act 文件**移植到另一个分支并提交/记录（不合并 behavior）；
3. 两边使用相同 act 能力后再继续对比。

否则会把“act 覆盖差异”误算成 substrate 差异。

> act/behavior 是可动态添加的内容；**operation 不是**。基线 op 清单见 [BASELINE-OP-ACT-SMOKE.md](BASELINE-OP-ACT-SMOKE.md) §10，缺失的 op 只能在 dev 基线补齐并重新打包，不能靠实验中途扩 op 绕过。

## 6. 实验协议

### 6.1 轮次

- 至少两轮：`IR` 世界 → `JS` 世界；每轮至少两组 session（可跨天）。
- 如果时间允许，再做一次反向顺序（JS → IR），减少学习效应；记录顺序。
- 不设死亡次数/通关速度等硬指标；目标是潜力与扩展性。

### 6.2 相同目标（两边一致）

1. 活过第一夜：木/石工具、基本食物、临时庇护所。
2. 铁阶段：找到铁矿、熔炼、铁工具/铁甲（至少一项）。
3. 一次**长跑策略**：escort 或区域采集，中途不切换，持续 ≥10 分钟。
4. 一次**打断策略**：采集/移动中遭遇威胁，behavior 内处理或切换，之后恢复。
5. 各至少写 1 个新 act 与 1 个新 behavior（由 subagent 编写）。
6. 不要求打末影龙；不为了指标刷时间。

### 6.3 操作方式

- 你选择 behavior、给参数、让它跑；不要逐 tick 微操。
- 周期性 `p2_status` / `p2_events` / `p2_observe`，而不是每 tick 查。
- 玩家/聊天由你处理；需要协作时再切换 escort/follow/交易策略。
- 出问题先停 behavior，再诊断；不要靠换 bundle 掩盖。

### 6.4 记录（每个策略）

| 字段 | 内容 |
| --- | --- |
| 规格 | 目标、输入、成功/失败条件、预期时长 |
| 分支/格式 | IR / JS；bundle 版本；commit |
| 作者 | subagent 标识；耗时/token；迭代次数 |
| 检查 | checker/运行期错误与修复 |
| 运行 | 成功/失败/取消；卡住与恢复；长跑稳定性 |
| 改动 | 是否改核心/运行时；内容与耗时 |
| 复核 | 另一个 agent 的 4 问（阶段/目标/下一步/失败出口） |
| 泄漏 | 是否把规划塞进 act/policy；是否出现巨型 act/policy |
| 备注 | 复用、可维护性、babysitting |

### 6.5 世界与干预

- 人类只做世界准备、备份、安装 bundle；游戏内救援（tp/给物品）必须记录为“干预”，不能算策略成功。
- 每个世界独立；不要用 IR 世界的进度影响 JS 世界。
- 遇到共享基线缺陷（op/act/provider）：停止该轮，记录，修复基线并同步两边后再继续；不计入 substrate 失败。

## 7. 已知限制（判定时必须考虑）

- JS 分支是**原型**：behavior 代码在 body 进程内的 `node:vm` 执行，尚未搬进隔离 runner；`defineBehavior` 形态；`progress` 未进入 status；无 external confirmation；`vm` 不是完整安全边界。
- IR 分支是现有 v1 内核；不要为了实验临时加领域节点；如确实需要，记为核心改动成本。
- 两分支的 `p2_check` 都支持 act/policy/format；但只有 JS 分支需要 `format:'js'`。
- 工具面/status 除格式外应一致；发现差异先记录，不要当成 substrate 优势。
- **开发期的外部 op 模块（`experiment.devOps`）必须在正式实验前关闭**：它破坏 binding 身份、让两个分支的能力集合不可比。若某个外部 op 要进入实验，先合并回 core/provider 并重打包，两边同时生效。

## 8. 判定与交付

实验结束后，你（DSH）写 `docs/M5.5-EXPERIMENT-RESULT.md` 或在当前分支写决策 memo，包含：

- 证据类别：表达上限、作者循环、长跑稳定性、组合复用、可观测性、安全性、维护局部性、agent babysitting；
- 具体案例与核心改动清单；
- 结论：沿用 IR / 转受限 JS / 混合；混合需给出边界与双维护成本；
- 不设硬指标，不以死亡/用时判定。

人类确认后再合并胜者到 `dev`；败者归档；共享 act/op/policy 可移植，behavior 内容不强行移植。

## 9. 新 session 的第一组动作

1. 读本文 + `ARCHITECTURE.md` + `BEHAVIOR-JS.md` + `BASELINE-OP-ACT-SMOKE.md`。
2. 确认当前分支与 bundle 版本：
   - `git branch --show-current`、`git log -1`；
   - `p2_status` 的 body 版本；
   - 对照 §2 的版本与 sha256。
3. 请人类安装/启动 IR bundle；先跑 §4 的工具级 smoke。
4. 按 §6 开始 IR 世界实验；记录日志。
5. IR 轮结束：停止 body → 人类卸载 IR → 安装 JS bundle → 启动 → §4 smoke → JS 世界实验。
6. 写决策 memo；不要合并、不要 push。
