# M3 G3 第一轮：body 外部 stop

> 2026-10-27。通过真实 body 进程 + Mineflayer provider，运行长 move act，再用 body `behavior.stop` 停止；不是 DSH 工具路径，但已是 P2 body 协议路径。

## 前置

- Vanilla 1.21.1，LAN `127.0.0.1:25575`
- hostile 已关闭，peaceful，固定白天
- provider 通过 `P2_MC_HOST/PORT/USERNAME` 注入 body
- 固定依赖：mineflayer 4.39.0 / minecraft-data 3.114.0 / minecraft-protocol 1.67.0

## 运行

```text
npm run build
node scripts/m3-g3.mjs 127.0.0.1 25575 P2_Bot
```

## 结论

- body 协议 `switch` 启动了 run-1；`behavior.stop` 返回后 `status.activeRun=null`。
- stop 响应时间约 **1ms**（仅表示命令受理/内存状态变更，不冒充物理停止完成）。
- 停止后的 0–200ms 仍有约 **0.237 格**位移，约一个步行 tick 的结算；200–1200ms 再增加 **0.019 格**，随后稳定。
- 这与上一轮“一个物理 tick 的结算余量”一致；**不是持续控制**。G3 判据按“控制释放 + 位移收敛”处理。
- 这次测试抓到一个真实 bug：`BehaviorRun.stop()` 原先只设置自己的 `stopRequested`，没有把 stop 传给 executor；长 act 会继续跑。已修复并加回归测试。

## /kick 测试（已完成）

操作员在长 move 期间执行 `/kick P2_Bot`。结果：

```json
{
  "ok": true,
  "before": { "x": -161.36922718799065, "y": -60, "z": -13.740649046001622 },
  "disconnect": {
    "status": "run-terminal",
    "elapsedMs": 15287,
    "activeRun": null,
    "pendingConfirmation": null,
    "health": "ready"
  },
  "observeError": "CONNECTION_LOST: Mineflayer connection ended: socketClosed",
  "heartbeatCount": 16,
  "stderr": ""
}
```

结论：

- `/kick` 后 run 终止，`activeRun=null`；
- provider 的 query 返回 `CONNECTION_LOST`，不再伪造旧世界数据；
- body 仍存活且 `health=ready`，stderr 为空；
- 16 次 heartbeat 排除了 owner lease 过期；
- 停止原因是连接丢失，不是 succeeded；不能用“被踢”冒充正常停止。

## /tick freeze 暂停测试（已完成，发现客户端预测问题）

操作员在长 move 期间执行 `/tick freeze`，约 15.5 秒后 `/tick unfreeze`。

结果：

```json
{
  "frozenDetected": true,
  "freezeAt": 3500,
  "unfreezeAt": 19000,
  "ageDuringFreeze": 56880,
  "positionAtFreeze": { "x": -1502.9506, "y": -60, "z": -13.7406 },
  "positionAtUnfreeze": { "x": -1570.9462, "y": -60, "z": -13.7406 },
  "activeRun": { "runId": "run-1", "status": "running" }
}
```

结论：

- `/tick freeze` **确实生效**：world age 停在 56880，持续约 15.5 秒。
- 但 P2 的 Mineflayer **客户端物理仍继续移动**，位置从约 -1503 变到 -1571；服务端 tick 冻结没有停止客户端预测。
- 解冻后 age 恢复（56880 → 56893），没有观察到服务端把 P2 拉回冻结位置。
- 因此：“暂停”对 P2 不等于客户端停止；`observe position` 在冻结期间是客户端预测值，不是服务端权威值。
- 这要求 Query/Act 层把 server tick/age 纳入来源/新鲜度元数据，并在暂停期间拒绝把客户端预测当成新世界事实。
