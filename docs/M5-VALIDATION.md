# M5 验证计划：小 IR 的能力边界

> 状态：**计划已冻结，尚未执行**。本文定义 G1 基础设施冻结集、G2 验证规格、G3 结论规则。执行证据另行记录，未执行前不宣称任何通过。
>
> 关联：[实施计划 M5](IMPLEMENTATION-PLAN.md#m5三层补齐与验证)、[IR 参考](IR.md)、[运行时](RUNTIME.md)、[隔离设计](ISOLATION.md)。

## 1. 目标

本阶段不追求“把 M5 全部做完”，而是取得一个架构结论：

1. **任务能否按预定语义完成或正确退出**——成功、失败、取消与收尾是否符合契约。
2. **表达这些任务时 IR 内核是否保持稳定，策略是否清楚留在 behavior 层**——新场景主要新增 behavior/policy/act，而不是修改执行器。

四个场景、四个策略变体、一组公共扰动是固定的验证范围；完成后停止扩展，不再增加玩法追求“全面证明”。

## 3. G1 冻结集

只补足本次验证需要的能力，不提前实现完整 M5。

### 3.1 分层与 op 切片

- provider 现有动作（look/move/jump/moveTo/stop）下沉为 **op**；op 声明留在核心，实现归 provider。
- 新增本次验证需要的 op：`dig`（单目标采集）、`pickup`（单目标拾取）；查询补足 `entities` 的物品名/数量/位置、`inventory`、`position`。
- 接线 `ActBroker`：生产链路当前把 provider 直接当 `ActPort`，G1 必须让 broker 真正持有账本、预算与清理。

### 3.2 act 层

- act 产物：单文件、无 `import`、强制声明 `queryOps`/`controlOps`（`stop` 隐式）、不可变 artifact。
- IR 的 `act` 节点改为确切 `ActRef`（definitionId + artifactId）。
- 共享 runner 承载 act hook 与 policy 调用（`role` 参数预留拆分）。

### 3.3 `decide` 与 policy

- 新增 `decide` 节点：一次提交、异步 pending、结果写入 local；不做表达式内联调用。
- policy 纯桥：无 op、无 I/O、有界；失败只使节点失败。
- 预算：单次 20ms、无响应 200ms；等待不占 tick 的 10ms 预算。

### 3.4 运行时冻结项

以下八项是场景成立的前提，**必须在 G2 开始前完成并冻结**：

| # | 项 | 现状问题 | 场景影响 |
| --- | --- | --- | --- |
| F1 | 反应式分支切换必须等待旧分支收尾确认 | [ReactiveRuntime](../src/core/node-runtime.ts#L350) 调用 `cancel()` 后忽略返回值，立即启动新分支 | S4 会在旧移动未收尾时启动拾取，违反“确认后才接管” |
| F2 | 启动新 act 前检查 predicate 完成条件 | 执行器只在根结束/失败裁决时读取 completion | S1/S3 的“达标即停”依赖这条 |
| F3 | `fail` 节点：计划主动失败 | 节点集没有业务失败原语，只能用表达式错误伪造 | S1 无候选、S3 资源不足、S4 声明失败 |
| F4 | 查询输出校验时效；guard 复用新鲜证据 | 只有 guard 检查 `validUntil`，查询节点输出不检查；guard 每 tick 重发查询 | 规格要求“观测年龄 ≤500ms”；S4 会每 tick 查询 |
| F5 | 查询默认期限对齐 1000ms | 实现默认 5000ms，与配置表不一致 | 全部场景的期限一致性 |
| F6 | `status` 暴露阶段、当前 act、等待原因、最近失败 | 当前只有 activeRun/lastRun/providerState | 可读性 4/4 检查没有数据来源 |
| F7 | `switch` 校验行为参数 | 直接创建 run，不校验参数 | S2“路线为空或参数非法 → 启动前拒绝” |
| F8 | 取消期间拒绝新 act、收尾期间不启动新动作 | 单控制位规则已在文档，需在 broker/执行器落实并验证 | 全部场景 |

### 3.5 实验设施

- 统一平坦测试区；排他：不允许其他玩家拾取、投递物品或无关战斗。
- 运营脚本：放置/移除掉落物、设置固定目标坐标、记录观测与状态快照。
- 观测记录格式：每步记录 `observedAt`、来源、年龄与判定依据。

### 3.6 冻结后的变更分类

G2 期间任何代码改动必须归入且只归入一类，分别计数：

1. **新增核心语义**（节点、表达式、执行器分支、checker 特判）；
2. **既有实现修错**（违反已声明契约的修复）；
3. **provider/op 适配**（游戏侧实现，不改变核心语义）。

## 4. 实验条件

| 项目 | 取值 |
| --- | --- |
| 到达容差 | 水平距离 ≤ 0.5 格，位于同一平面 |
| 决策/到达/成功证据 | 通过校验、年龄 ≤ 500ms 的观测 |
| 查询期限 | 1000ms，零隐式重试 |
| 单 act 总期限 | 最长 30s，可声明更短 |
| 停止与收尾期限 | 2000ms；未确认则报告故障，不伪造停止成功 |
| 单次实验观察上限 | 180s；超时由人停止，记“验证未通过”，不伪造业务成功 |

共同规则：

- 人工取消后，收尾确认才成为 `cancelled`，不得继续后续动作。
- 普通业务失败经收尾后成为 `failed`；持续行为被正确取消也算验证通过。
- 清理无法确认时保持故障与停止未完成，禁止接管新动作。
- 未知、查询失败、观测过期不等于“没有候选”。
- 失败名称是**验收标签**，可映射到既有或场景自定义错误码，不要求逐个新增核心错误类型。

## 5. 场景

### S1 拾取最近的一个掉落物

**任务**：测试区放三个分开的掉落物，均为物品 T、各 1 个；P2 的 T 初始为 0。behavior 查询候选与位置，policy 按快照中的距离选最近；等距按稳定实体 ID。选中后固定目标，不因其他物品变近而换目标。

**成功**：选择结果确为该快照最近；新鲜背包查询确认 T 从 0 到 1；未拾取其他掉落物；act 与 broker 收尾完成；behavior `succeeded`。

实体消失本身不能证明拾取成功；被他人拿走、合并或外来同类物品使本次证据无效。

**失败出口**：

| 情况 | 处理 |
| --- | --- |
| 完整有效的候选为空 | `failed / NO_CANDIDATE`，不启动移动 |
| 目标被移除且库存未增加 | `failed / TARGET_GONE`，本场景不重选 |
| 不可达、容量不足、动作超时 | 明确失败，不改捡其他目标 |
| 无法取得有效库存证据 | 不能成功，按查询/验证失败退出 |

**反例**：选择完成后、拾取前移除目标，必须失败，不得把实体消失当成功。

**变体 V1**：最近优先改为最远优先，只改 policy。

### S2 持续巡逻

**任务**：路线参数为 A、B、C 三点，顺序循环 `A→B→C→A→…`；每点经新鲜位置确认到达后等待 500ms 再前往下一点；只有确认到达才推进路线。

**通过**：观察到六次有序到达 `A,B,C,A,B,C`；此时仍 `running`；在下一次移动进行中发 stop；收尾完成后 `cancelled`，不再启动移动。**不存在正常业务成功终态**；两圈只是观察长度。

**失败出口**：

| 情况 | 处理 |
| --- | --- |
| 路线为空或参数非法 | 启动前拒绝（F7），不创建活动运行 |
| 航点不可达或移动超时 | 整个 behavior 失败，不隐式跳点 |
| 位置查询失败、无法确认到达 | 不推进路线，按明确错误退出 |
| 移动收尾失败 | 保持故障，不开始下一航点 |

**反例**：B 不可达时必须失败，不得跳到 C。

**变体 V2**：改为往返 `A→B→C→B→A→…`，只改 behavior/policy。

“下一个航点/当前方向”属于合理业务状态；`programCounter`、跳转编号等模拟解释器位置的状态应计为机械状态。

### S3 有限采集

**任务**：目标为背包中 T ≥ 4，初始 2。测试区六个固定坐标目标（参数传入），每个正常产出 1 个 T；不扩大搜索、不换工具、不采其他种类。流程：检查库存 → 未达标选目标 → act 采集一个 → 重新检查。

act 只能处理一个已选目标，不得出现承包整个配额的动作。

**成功**：新鲜库存查询确认 T ≥ 4；最后动作及收尾完成；不再启动采集；`succeeded`。启动时已达标应直接成功，不执行采集。采集次数、破坏方块数不能替代库存证据。

**失败出口**：

| 情况 | 处理 |
| --- | --- |
| 区域资源耗尽且库存不足 | `failed / INSUFFICIENT_RESOURCE`，保留已取得成果 |
| 所选目标失效 | 本基线直接失败，不隐式换目标或重试 |
| 工具/容量/可达性/超时 | 明确失败，不改任务条件 |
| act 报成功但产出证据不成立 | 不计采集成功，按结果验证失败退出 |
| 库存未知或过期 | 不判达标，也不当作 0 |

**反例**：初始 2、仅提供 1 个可采集目标，最终 3，必须 `failed / INSUFFICIENT_RESOURCE`。

**变体 V3**：达标后必须返回起点并再次确认库存与位置才算成功；只改计划与完成条件，复用既有 act。

### S4 巡逻途中拾取，再继续原路线（关键场景）

**任务**：P2 已到达 A、正前往 B（拾取路径不经过 B）。此时附近出现一个掉落物。必须发生：前往 B → 新观测确认掉落物 → 取消原移动并确认收尾 → 拾取 → 新建移动重新前往 B → 确认到达 B → 继续 C。全程同一个 run；拾取完成后继续的是**尚未到达的 B**，不得推进到 C，不得复活已取消的移动实例。

**通过**：掉落物出现时原移动仍在进行；在原移动自然完成前打断；原移动收尾确认后才启动拾取；新鲜库存确认拾取；重新到达 B 再到达 C，路线无跳点或重复推进；behavior 仍 `running`；最后人工 stop，`cancelled`。

**失败与恢复**：

| 情况 | 处理 |
| --- | --- |
| 拾取目标失效且未获得物品 | 按声明恢复到巡逻，重新前往 B；不无限找替代物 |
| 拾取不可达或其他未声明失败 | 整个 behavior 失败 |
| guard/policy 失败 | 按分支错误退出；已有活动 act 仍须收尾 |
| 原移动清理失败 | 保持故障，禁止启动拾取 |
| 高优先级判断 unknown | 不得当作 false 启动低优先动作 |

**反例**：打断移动后移除拾取目标，应按声明恢复到 B。

**变体 V4**：“目标失效后继续巡逻”改为“整个任务失败”，只改 behavior 恢复规则。

## 6. 公共扰动

放入既有契约或状态安全套件，用受控输入，不建立游戏模拟器。

| 扰动 | 必须观察 |
| --- | --- |
| policy 未返回时取消，旧结果随后到达 | 停止可推进；旧结果不能写状态或启动动作 |
| 取消与成功同批 | 按取消优先裁决 |
| 决策观测 unknown/过期/超时 | 不冒充 false 或空集合，不放行依赖该证据的新动作 |
| 活动分支中的 policy 失败 | 正确退出并收尾活动 act；共享 runner 丢失不能忽略 |
| 清理失败 | 不报告停止完成，不授予下一个 act 控制权 |

## 7. 指标

| 指标 | 通过标准 |
| --- | --- |
| 核心稳定 | 冻结后新增节点、表达式语义、checker 特判、执行器策略分支均为 **0** |
| 策略归属 | 隐藏完整巡逻/配额采集的 act 为 **0**；返回指令序列或程序计数器的 policy 为 **0** |
| 取消责任 | behavior/policy 自建停止标志或取消轮询为 **0**；act 仍履行 stop/cleanup |
| 可读性 | 非作者仅看计划、接口说明与 status，能回答当前阶段、当前目标、正常下一步、失败出口，**4/4 正确** |
| 状态负担 | 每个 local 都能解释业务含义；纯模拟执行位置的状态为 **0** |
| 改动局部性 | 四个变体都不修改核心，也不靠扩大 act 职责完成 |
| 诊断成本 | 不新增日志即可从 status/事件指出当前阶段、等待对象、最近失败 |

节点数、源码行数、locals 数量与耗时只记录，不设硬上限，避免把复杂度藏进 act。

## 8. 停止规则与结论

范围固定为：四个正常轨迹、四个业务反例、四个变体、一组公共扰动。完成后停止。

| 结论 | 条件 |
| --- | --- |
| **继续采用小 IR** | 全部场景与变体在冻结内核上表达成立，计划可读，策略未逃入巨大 act/policy，运行证据符合预定语义 |
| **触发替代方案对照** | 至少两个不同场景或变体必须增加核心语义，或只能靠隐藏完整策略实现；允许一次有界收缩，仍不成立则暂停 IR 扩展 |
| **暂不能判断 IR** | 缺 op、观测证据不足、隔离未就绪或实现违反已定契约；记为准备阻塞/实现失败，不算 IR 通过，也不算不适合 |

每个场景单独结论，不合并成总评；证据不足的场景不能计入“继续采用”。

## 10. 与其他部分的关系

- **隔离**：G2 的 runner 只要求共享模式与纯桥/op 桥分离；独立 policy runner 是否拆分在 G3 后决定，见[隔离设计](ISOLATION.md)。
- **来源与启用**：G2 的 act/policy 均由本会话编写（session-authored），不涉及 `imported`。
- **发布**：G2 不是发行验收，不宣称可玩或支持整合包。
